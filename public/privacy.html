This notice explains how the operator of this AutoApply Cloud deployment collects, uses, shares, and retains information. AutoApply is a review-first job-search workspace: it stores the information you choose to provide and connects to external services only when you ask it to.

Information we collect

  • Account information: your email address, authentication records, and account identifiers managed through Supabase Auth.
  • Applicant information: profile details, skills, education, preferences, résumé PDFs, and résumé-derived suggestions.
  • Job-search information: job descriptions, company and contact details, application links, drafts, approvals, send history, and status updates.
  • Connection information: connection status, authorized scopes, provider account metadata, encrypted OAuth tokens, encrypted user-supplied Google Web OAuth client credentials, or opaque managed-browser context identifiers when a supported connection is enabled.
  • Operational information: automation job states, audit events, request identifiers, security events, Turnstile challenge results, and limited technical logs needed to operate and protect the service.
  • Gmail abuse-prevention records: domain-separated SHA-256 hashes of the Google provider account identifier and normalized recipient, a random event identifier, outcome, and expiry. These rows contain no AutoApply user ID, plaintext email address, message, or OAuth token.

Your Groq API key

Your Groq API key is stored only in this browser's local storage. AutoApply sends it to its backend in a request header only when you validate the key or request an AI-assisted operation. The application is designed not to save the key in its database, logs, analytics, or synced account data. Anyone with access to this browser profile may be able to use or remove the locally stored key. You can delete it at any time from Profile, and you should remove it before using a shared device. Ordinary sign-out deliberately preserves the key for that user on that browser. Explicit key removal, successful account deletion, clearing site data, or deleting the browser profile removes it. The application namespaces keys by user so another signed-in AutoApply user is not shown your key.

Your Google OAuth client credentials

Most users connect Gmail with the deployment's platform-managed Google OAuth client and do not provide Google Cloud credentials. If you choose the advanced user-managed option, you provide a Google Web application OAuth client ID and client secret from a project you control. A Google Cloud API key is not sufficient and is not accepted as Gmail authorization.

AutoApply sends the ID and secret to its authenticated backend, encrypts both before database storage, and stores only ciphertext in a table restricted to the trusted service role. The saved secret and ciphertext are not returned to your browser, placed in local storage, or exposed through browser database policies. The trusted server can decrypt them only when needed to create or refresh the Gmail connection. Connection status may show a masked client-ID hint. You must disconnect Gmail before replacing or deleting this saved client so an existing refresh token cannot be silently moved to different client credentials.

How we use information

We use information to:

  • authenticate you and keep each account's workspace separated;
  • store and parse résumés, maintain your job pipeline, and generate requested drafts;
  • send an approved message through a connection you authorized;
  • prepare supported application handoffs and show durable task progress;
  • enforce review, send-rate, duplicate-recipient, and security safeguards; and
  • diagnose failures, prevent abuse, and improve reliability.

When information is shared

Information is disclosed only as needed to operate the service or perform an action you request. Service providers may include Supabase for authentication, database, and private file storage; Vercel for application hosting and request execution; Groq for AI requests made with your key; Google for Gmail authorization, token exchange or refresh using the OAuth client you selected, and approved sends; Cloudflare for Turnstile bot challenges; and a managed-browser provider when you explicitly start a supported browser handoff. Each provider processes information under its own terms and privacy practices.

AutoApply does not sell personal information. It does not ask you to provide your LinkedIn password and does not store LinkedIn credentials. LinkedIn application activity is manual/partner-only: the product does not claim that LinkedIn login authorizes Easy Apply automation, and prohibited or unsupported automation is not offered.

Browser storage and cookies

Supabase stores authentication session material in your browser so you can remain signed in. AutoApply also uses local storage for your Groq key and limited interface preferences; it does not persist a Google OAuth client secret there. Signing out removes the AutoApply authentication session but does not remove the user-namespaced Groq key. Remove that key explicitly before using a shared device. Account deletion attempts to remove it; clearing site data or deleting the browser profile removes browser-held values independently of the service.

Retention and deletion

Workspace records are retained while your account is active and for any limited period required for security, dispute resolution, or legal compliance. Deleting a résumé removes that résumé's database metadata and private Storage object; it does not delete existing jobs, applications, drafts, send history, or audit history. Disconnecting Gmail serializes against pending OAuth callbacks, deletes the local connection/token rows, and makes a best-effort Google revocation request. If Google does not confirm revocation, remove AutoApply from Google Account settings as an additional safeguard. Disconnect does not itself delete a separately saved user-managed OAuth client; after disconnect, you may keep it for a later connection or delete it with the advanced connection control. Replacing or deleting it while Gmail is connected is blocked. Account deletion removes it with the rest of the tenant's server-side secret records.

Account deletion removes tenant workspace rows, private résumé objects, and supported provider connections. To prevent deletion/recreation from evading Gmail caps or duplicate-recipient protection, pseudonymous provider-account/recipient hash rows may remain after deletion. Their active use expires no later than 90 days from creation (and therefore no later than 90 days after account deletion), and normally sooner with the configured duplicate window. Expired rows immediately stop affecting caps or duplicate checks. An hourly database job and the next send-reservation path physically delete expired rows; a failed cron run can delay physical deletion and is an operator-monitored condition. The rows cannot be read by browser users.

Security

AutoApply uses authenticated API requests, row-level account isolation, private résumé storage, encryption for stored provider tokens and user-managed OAuth client credentials, restricted OAuth scopes, and redaction controls. No internet service can promise absolute security. Protect your password, sign out of shared devices, and disconnect a provider if you believe access has been compromised.

Your choices

You decide what profile and job information to provide, whether to upload a résumé, whether to save a Groq key in a browser, whether to use the deployment's Google OAuth client or save your own, and whether to connect Gmail or another supported provider. You can edit drafts before approval, decline to send, use a manual handoff, disconnect services, and delete stored resources through the workspace.

Age, international use, and changes

The service is intended for people who are legally able to seek work and enter into these terms; it is not directed to children. Depending on your location and the operator's providers, information may be processed in another country. We may update this notice as the product or applicable requirements change. A revised effective date will be shown here, and material changes should be communicated through the service.
